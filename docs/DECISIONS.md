# Decisions

- **2026-10-09 Stack.** TypeScript, Express 5, React 19 + Vite, SQLite via node:sqlite everywhere (tests use in-memory), Zod at the API boundary, Anthropic SDK with structured outputs (`output_config.format`) and `output_config.effort`. No Next.js, Supabase, job queue or ORM: one user, one process.
- **2026-10-09 Model.** Default `claude-opus-5-5`. Effort: `high` for everything by default (edits moved from `medium` on 9 Oct: on the rhyme-keeping brief E4, `high` gave more natural options for ~1 cent more; one sample, directional). Both adjustable in Settings. Rates snapshot in `server/engine/writer.ts` dated 2026-10-08.
- **2026-10-09 Literal edits skip the model.** "Change X to Y" with no creative words is applied directly (whole-word, case-sensitive first). Free, exact, recorded as `edit:direct`.
- **2026-10-09 Constraint checks.** Model reports constraints it read; a deterministic regex extracts counts and quoted start/end phrases; code validates. Failing options are shown with a ✗ label, not hidden, and not auto-repaired (no second paid call). Revisit if Sam finds this noisy.
- **2026-10-09 Spend.** Daily $10 / monthly $150 caps by default. Before each call the worst-case cost (max tokens × output rate) is reserved under a lock; actual cost from reported usage replaces it. Failures with unknown usage keep the reservation (counted, not assumed zero).
- **2026-10-09 Hosting.** Render web `0.5c-512mb` ($7) with a 1 GB disk ($0.25); ~$7.25/month. Data is one SQLite file (`node:sqlite`, built into Node 22) at `/var/data/songroom.db`, WAL mode, synchronous=FULL. PGlite was tried first and abandoned: it peaked at 650–860 MB on boot and Render killed it at 512 MB. SQLite boots at ~84 MB; verified data survives a hard kill. A separate Render Postgres ($6) was rejected because no existing paid database exists to share.
- **2026-10-09 Design.** Lyric pages are yellow legal-pad sheets (blue rules aligned to line height, red margin, blue-black ink, Newsreader); chrome is quiet graphite with Instrument Sans. Margin doodles stand in for illustrations.

- **2026-10-09 First live run (real Opus 5.5, prompt p1.0).** All 12 briefs succeeded, $0.33 total (ideas ~4c, lines ~2–4c, edits ~2c, literal edits free). Hard checks all passed. Weakest: E4 (rhyme kept by decorative words). Prompt p1.1 added rhyme guidance and quoted-word bans; E4 improved but is still the area to watch.
- **2026-10-09 API key.** Sam's key is multi-workspace, so requests send `anthropic-workspace-id` (Default workspace, org "Romans") via `ANTHROPIC_WORKSPACE_ID`.

- **2026-10-10 Prompt p2.0 is the default; the research pack is not.** The 9 Oct prompt (p1.1) forced every idea into a realisation story with a title twist and a domestic detail (audit: `research/PLAN.md`). p2.0 removes that, lets ideas take the shape the brief asks for, makes options lines-only, and tells the writer to admit an unknown reference instead of inventing it. p1.1 is kept verbatim as the baseline condition in Settings → Experiments. Craft notes from the research pack (`research/pack`) are behind the `craftPack` setting, off until Sam has judged the blind comparison.
- **2026-10-10 Research pack = JSONL files in the repo, keyword retrieval.** No vector store, no new service. `server/engine/pack.ts` loads `research/pack/*.jsonl` at boot and picks at most 2 cards + 2 reference profiles + 1 teaching pair by tag/keyword match (`PACK_LIMITS`). Sources are provenance only and never reach the writer. Each run records the prompt variant and the record IDs used (`runs.prompt_version`, `runs.request.pack`).
- **2026-10-10 Blind experiments.** `server/experiments.ts`: eleven fresh briefs × repeats × three conditions (A p1.1, B p2.0, C p2.0+pack), same model/effort/settings; outputs shuffled, conditions revealed only after a vote; $5 batch cap on top of the normal caps. Literal edits still skip the writer and are not part of the comparison.

- **2026-10-10 Approved design built without touching the writing prompts.** The new screens need new output shapes (a batch of springboard ideas; replace/add suggestion sets; reference lookups). These are templates `p2.0/ws1` in `server/engine/prompts.ts`: they reuse p2.0's writing instructions and add only the shape and the carried context (rhyme by sound, rhythm by syllable count, meaning, narrator). Nothing was tuned to the partial blind votes (2 of 22). `craftPack` stays off. All 22 trials and both votes are untouched; the backup now includes experiments.
- **2026-10-10 Design server = `server/studio.ts`.** Additive migration 3 (fragments, suggestion_sets, refs, client_actions; new idea/song columns). Old threads, ideas and songs keep working. Every paid tap carries a client key so double taps are one request; a suggestion is applied from the server's stored copy, never from what the browser sends back.
- **2026-10-10 Design tokens.** DM Serif Display / DM Sans / Caveat (bundled via @fontsource, no Google Fonts call), ochre / sage / blue palettes per idea, replacing the yellow legal-pad look of 9 Oct.
- **2026-10-11 Craft notes scoped to edits.** Sam judged all 22 blind trials: old prompt 5, corrected prompt 7, corrected + craft notes 6, none 4, no stars. Overall a wash. On the four precise-edit trials the notes won 3 and the old prompt 0; on ideas the old prompt won 3 of 4 judged. `craftPack` is now a scope (`off` | `edits` | `all`), default `edits`. p2.0 stays the default prompt. 11 of 18 picks were position 1, so a position effect is possible; next run should shuffle per viewing. Full table in `research/SUMMARY.md`; votes in `research/pack/sam_judgments.jsonl`.
- **2026-10-11 Ideas grounded in the chart (Sam's request).** Subjects come from what entered the Spotify US Top 50 over three years (`research/charts`), picked by the engine per idea (`engine/barometer.ts`), weighted by genre, with recently seen subjects less likely; his direction overrides. The writer's standing instructions (p2.0) are unchanged; only the idea brief changed (`ws2`; `ws1` kept verbatim). Data came from Internet Archive snapshots of kworb.net's copy of Spotify's US daily chart, read through the browser because the workspace cannot reach those sites.
- **2026-10-11 Rework is a new idea, not an edit.** A reworked idea is its own row (`parent_id`, `feedback`), shown in place of the original; Previous returns to it. Lines he marked "keep" are put back by the engine if the writer drops them. The title and concept, when kept, are copied, not regenerated.
- **2026-10-11 The song page.** He said he will never type lyrics in the app; it should generate a journal page that becomes a draft. Lines on the page are fragments (`source='writer'`, with the `ask` that produced them); one tap adds a line to the end of the draft (or after his cursor). Nothing enters the draft by itself.
- **2026-10-11 The diary-pop lane is a choice, not the default.** Sam's hunch ("most songs are female relationship angst, conversational, Instagram-poet style") was tested (`research/charts/COHORT.md`): the lane is about one hit in six; relationship-heavy, yes (83%); conversational, yes (57% vs 34–40% elsewhere); Instagram-poet, no (8%), and critics never make that comparison. So "Diary pop" is a genre chip with its own subject mix and style note (specific, talky, wry, a situation not a mood), while Pop stays the default mix. Naming its writers in the direction picks the lane automatically.
- **2026-10-11 Rhyme is expected and checked (prompt p2.1).** Sam: "there's usually only 1 rhyme in the whole thing. Needs more attempts at clever rhyming." p2.0 told the writer natural speech beats rhyme; p2.1 replaces that one bullet (everything else verbatim): rhyme is expected in any run of lines that belong together, and a good one is multi-syllable, across a word boundary, or an ordinary word against a name; slant must still rhyme by sound. The idea's first lines are now one four-line block with a scheme, and the writer names its rhyme pairs. The engine checks every block by sound (`engine/rhyme.ts`, CMU pronouncing dictionary: perfect / slant / identical) and sends the ones that fall short back once in a single extra call; the better-rhymed version is kept, and the receipt records before/after scores. No new dependency beyond the dictionary.
- **2026-10-11 Checking the writer without touching his board.** After live tests left his app on a test idea with Diary pop on, `POST /springboard/preview` writes a batch to a direction given on the spot, saves no idea, and keeps the run and receipt. Live checks use it from now on.
- **2026-10-11 The hang: after the session, not live.** Sam: writing sessions start with an hour of the artist talking about their life, and someone occasionally says "that line would be a great title". Built as a page (Hang) that reads a session's transcript afterwards and lists the titles, concepts and lines said in the room, each with who said it, when, and the sentence around it. Not a live listener: a phone web app cannot listen for an hour, and nobody acts on a title mid-conversation. Two ways in: paste a transcript (no setup; iPhone Voice Memos makes one), or upload the recording, transcribed by Deepgram (one key, `DEEPGRAM_API_KEY`, about 46c an hour, billed into the receipts as a `transcribe` run). The reader's rule is verbatim only, and the engine enforces it: a candidate that is not in the transcript word for word is dropped, and a loose context is replaced by the transcript's own window. The transcript is cleared once the candidates are out; the recording is deleted after transcription. A candidate becomes an idea on the Write screen (title = the words, first line = the moment) or a saved idea in the journal.
- **2026-10-11 The writer learns from his notes (prompt p2.2 + lessons).** Sam, on an idea that rhymed "call" with "hall": "Hall isn't an appropriate word for this subject, it sounds like a wedding or church. Hall shouldn't have been an option. Will it learn from me if I told it that?" Two things. (1) p2.2 adds one test to p2.1's rhyme bullet, everything else verbatim: the word that carries a rhyme has to be a word the scene would contain, with no stray picture attached; if it isn't, change the earlier line's end word. The idea brief and the rhyme retry say the same in one phrase. (2) `engine/lessons.ts`: the call that reworks an idea to his note also boils the note down to one standing instruction, if there is one in it (a word that is wrong and why, a habit to drop, a register he wants; nothing for "make it sexier" or "keep the title"), kept in a `lessons` table and read by the writer, newest first, with every idea, line and edit (`svc.tasteFor`, after his taste notes). The reworked idea shows "Noted for every idea from now on" with a forget link; Settings lists them with the note each came from, a Forget button, and a box to add one in his own words. Near-duplicates are one. This replaces, for corrections, the "use this note for new ideas too" switch, which copied a whole sentence into the direction and still exists for steering. A rework can be run as a `preview` (saves nothing) so the writer can be checked without touching his board.
- **2026-10-11 Lines built around the title; Browse ten at a time (template ws4).** Sam: "How am I supposed to just generate and browse a bunch of ideas that are just good relationship titles (with a concept and a few lines)… the few lines should be based around the title, like how you would use it in the chorus. Some should start with the title, some should end with it. Some could maybe just have it in passing." (1) An idea's lines are now the part of the chorus where the title lands. The engine assigns each idea in a batch one of three placements (`engine/hook.ts`: open, close, passing), spread across the batch, and checks the title is in the lines word for word; a block without its title goes back in the same single retry call as a block that doesn't rhyme, and the better version by one score (rhyme pairs + 2 for the title being there) is kept; the receipt records want/before/after. Which of the three a block actually lands on is not enforced, only that the title is there; variety across the batch is the point. (2) A Browse page (`#/browse`, `studio.startList`): ten ideas in one call, in state `listed`, shown as cards (title, concept, chorus lines) for the direction they were written to, newest list first; never pulled into the one-at-a-time queue; tapping one makes it the idea on the Write screen. Subjects default to the five relationship subjects of the chart mix ("Relationships" / "The chart mix" toggle); the genre chips are the same direction as Write. A list is one writer call of ten (plus the retry), so a few times a batch of three.
- **2026-10-12 Keep learning: lessons scoped and superseded; a profile learned from what he does; concepts at hit scale (template ws5).** Sam, after a session: the concepts are "things I would never hear in songs", the writer is "using the ideas it learned in the wrong way", "can you somehow keep learning?" The record showed what he meant: his note "Artist is British, shouldn't be specifically American references" had been filed as a standing rule about him ("Sam is British and wants folk… pub, van, Co-op"), his correction ("shouldn't be English-coded either") as a second rule contradicting the first, and both were read with every idea; 61 ideas in the day, one page made. Three changes. (1) A lesson now has a scope the rework call decides: `standing` (every idea from now on), `session` (about the artist or song he is writing today; expires after 12 hours), or `none`; it is worded as an instruction about the writing, never a fact about Sam; and a corrected lesson lists the numbers of the earlier ones it replaces, which are retired. The brief tells the writer to apply a lesson by avoiding the mistake it names, never by building an idea around it. (2) `server/learning.ts`: every idea he sees ends one of a few ways (page, save, rework note, picked from a list, left in the list, passed over); after every ten new ones, a small call (`reflect`, effortEdit) reads the last forty with their outcomes and his direction at the time, and writes for itself what he goes for and what he passes on, with titles as evidence, strong signals only for "goes for", patterns only for "passes on". Stored in settings (`taste.learned`), shown in Settings → What it's noticed (take stock now / forget), read with every brief after his taste notes and lessons, which outrank it. (3) The concept is now "the song in one breath", at most 25 words, a stance a few million people have been in, with no backstory; and the brief shows eight real hits' situations (from `research/charts/classified.json`, songs that sat a month or more in the top 50, our words) as the scale to write at. The two bad lessons were removed from his list; the neutral one ("no American markers, no English-coded ones") was re-added for the session.
- **2026-10-13 Titles for the next section; bringing a song in.** Sam, mid-song with a verse written and a Noah Kahan reference: "looking for the title for the next section" — he had typed the whole lyric into the direction box because there was no other way in, and got ideas instead of an answer. Two things. (1) Write → "Or bring a song you're already writing": paste the lyric so far, say what you need, and it opens as a song page with eight titles on their way. (2) On any song page, "Find the title for the next section" (`studio.findTitles`, task `titles`, table `title_sets`): the writer reads the lyric as it stands (plus his notes, the page's lines, the song's context and references, or the direction's reference when the page has none, and the hit-scale examples) and offers eight titles, different in kind (a plain phrase, one lifted or turned from his own lyric, an image from it, the stance from the far end), each with the two lines of the section it lands in and twelve words on what in his lyric it pays off. "Use this title" sets the song's title and puts its lines on the page to tap into the draft; "Eight more" avoids the ones already offered. Newest set first; earlier sets stay on the page.
- **2026-10-14 Four destinations: Ideas · Create · Journal · Hang (the simplification plan).** Sam's plan (`Songroom_Simplification_Plan_for_Claude.md`): the Write screen had a genre grid, a direction form, the rework box, a checkbox, the ten-title link, scraps and a song import competing on one page, and the song page put generated lines before his own draft. Now: **Ideas** is one idea near the top (title, concept, seed lines), Another idea, Save, Start writing / Continue writing, Add a thought (his exact words, kept as a fragment, saveable on its own), a compact "For you" selector (genre, a line, a reference; steers the next idea only) and a ⋯ menu (Develop in Create, Previous, History). **Create** is one input ("What are you working on?") that takes a brief, pasted lyrics, a title request or a line problem, with Reference and a collapsed Fine-tune (what you want back, rhyme word, rhythm line, narrator, words to keep); Generate infers the task through the thread engine (one working brief = one thread, follow-ups go to it, results shown one at a time with Previous/Another, Save, Start writing); pasted lyrics get an explicit Open in Journal that makes a draft of them exactly; `?idea=` develops an idea to a note (the rework, which also teaches the writer; the Ideas screen stays put via `stay`); `?song=` works for a song and Use in song puts lines on its page as scraps, never into the draft. **Journal** gains New song (empty or pasted); the song page is title (editable in place), the draft, one Help field with quick actions for the selection (Rewrite, Find a rhyme / Continue, Find the title, Lock), one suggestion at a time with Keep / Another / Previous and Undo, and a collapsed Scraps drawer (concept, seed lines, titles, lines the writer offered, his own, earlier suggestions). **Hang** is unchanged in substance; its candidates get the shared actions (Save, Develop in Create, Start writing) and the idea they make carries the session. Bottom tabs on a phone (hidden while typing, back a beat after focus leaves so a tap above the bar lands), the same four in the top nav from 700px. Old links resolve: #/write → Ideas, #/browse → Create, #/song, #/idea, #/session unchanged. The Browse page is gone; its backend (`/browse`, `/browse/list`) stays. Nothing stored was deleted. Checked by a browser journey script (`tests/journeys/simplification_journeys.py`, 34 checks) at 320/393/430, desktop and dark.
